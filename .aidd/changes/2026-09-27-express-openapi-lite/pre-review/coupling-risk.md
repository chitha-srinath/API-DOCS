| CR-1 | HIGH | architecture.md C0/ADR-18/ADR-11, ST-001, ST-005 | The dual ESM/CJS build duplicates every module-level identity: `META: unique symbol`, the recorder idempotency guard symbol and the `[MOUNT]`/`[CHILD]` keys. Nothing requires `Symbol.for(...)`. | App code `import`s the package while a CJS dependency `require`s it, so both `dist/index.js` and `dist/index.cjs` load. The recorder installs twice on the same Express prototype (the guard symbols differ, so `use` is wrapped twice). The walker from copy A reads `[MOUNT]` under copy B's symbol and finds nothing, so every Express 5 route falls back to its local path plus a warn. The parity test compares only `Object.keys` and will not catch this. Fix: require `Symbol.for('express-api-docs.*')` for all four symbols and add a mixed import+require test. | architecture.md:77, :117, :124; stories/ST-001-scaffold.md:100 |
| CR-2 | HIGH | ADR-18, ADR-13, ST-005 | The import-time recorder depends on *which* Express module instance it resolves. Express is only a peer, and the plan does not say how `recorder.ts` gets `express`, or how ESM and CJS resolution pick the same instance the consumer uses. | Case 1: a pnpm or monorepo install has two Express copies, so only the resolved copy is patched and routers from the other copy get wrong paths with only a warn. Case 2: the repo's own tests install both `express` and the `express4` alias (ADR-13). An import-time hook can only patch one of them, and no story defines an explicit install API for the other. Fix: expose `installRecorder(expressModule)` (used by tests and by users with non-standard resolution) and specify how the default is resolved. | architecture.md:119, :124, :278-279; stories/ST-005-introspection.md:119, :155 |
| CR-3 | MEDIUM | ADR-18 | At import, the recorder wraps `express.application.use` and the router prototype's `use` for the whole process. Our annotations are lost or bypassed, and prefixes disappear in production only. No fixture covers this (counter-arguments.md "most likely failure mode"). | CR-6 | MEDIUM | ST-004/005/006 registry seam | Three stories share the `RouteRegistry` shape `{method, localPath, meta, validatorFn, handlerFn}`, but it is described only in prose.
