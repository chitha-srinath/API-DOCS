| PF-1 | HIGH | architecture.md C0/C12, ADR-18; ST-001 package.json shape | `META` is a module-local `unique symbol`, and the recorder is guarded "by a symbol". In a dual ESM+CJS build each format gets its own copy of the module, so local `Symbol()` values differ between copies (dual-package hazard). The ecosystem convention for cross-copy tags is `Symbol.for('express-api-docs.meta')`. | A consumer's app loads `route()` through `import` (ESM copy), and a shared internal lib calls `createApiDocs()` through `require` (CJS copy). The introspector reads `[META]` with the CJS symbol, finds nothing, and classifies every typed route as `source:'plain'`, so the schemas vanish from the spec. The same split installs the `use` recorder twice, because the ESM guard symbol does not match the CJS one. That double-annotates layers. | architecture.md:36 (`META: unique symbol`), architecture.md:83 ("idempotent (guarded by a symbol)"), ST-001-scaffold.md:78 (dual `import`/`require` exports) |
| PF-2 | HIGH | ADR-04, C9, AC-004 | `zod` is a required peer, and `zodAdapter` is exported from the main barrel `.`. That contradicts ADR-04's own rationale that "a user on a future non-Zod adapter must not need Zod". The ecosystem convention (for example trpc, hono validators, ts-rest) is `peerDependenciesMeta.zod.optional: true` plus a subpath export such as `express-api-docs/zod`. | A Valibot user installs the package without zod. npm 7+ auto-installs the required peer, or pnpm fails in strict mode. With an optional peer instead, `import { createApiDocs } from 'express-api-docs'` still evaluates `adapter/zod.ts`, which statically imports `zod`, so the result is `ERR_MODULE_NOT_FOUND` at startup. Moving it later is a semver-major break, because the first publish fixes the barrel (impact-report.md:14). | architecture.md:69 (ADR-04 rationale), architecture.md:45 (C9 exports include `zodAdapter`), ST-001-scaffold.md:78,87,110 (zod required peer asserted exactly) |
| PF-3 | MEDIUM | ST-001 package.json shape | The emitted `.d.ts` files reference Express types (`Request`, `RequestHandler`, `Router`), but no `@types/express` peer is declared. Middleware packages that ship Express types in their public signatures normally declare `@types/express` as an optional peer. | A TypeScript consumer on Express 4 without `@types/express` gets `Cannot find module 'express'` type errors, or implicit `any`, in `node_modules/express-api-docs/dist/index.d.ts` under `skipLibCheck:false`. A consumer on `@types/express@4` may also hit mismatches, because the package was type-checked only against `@types/express@5.0.6`. | ST-001-scaffold.md:78 (peerDependencies list), architecture.md:172 (`@types/express 5.0.6` devDep only) |
| PF-4 | MEDIUM | ADR-18 vs ecosystem convention | An import-time global prototype patch of `Router.use` and `application.use` is atypical for Express middleware, which is conventionally inert until mounted. Examples are swagger-ui-express, the cited precedent, and express-list-endpoints, which walks without patching. The plan accepts this pattern (spike-backed). It still needs an explicit opt-out and a documented `sideEffects` entry that lists only the recorder file, not the whole package. | An ESM bundler (esbuild or webpack) sees `sideEffects` unset, or set to `true` for the whole package, and cannot tree-shake anything. Alternatively, a user of a hot-reload or test runner that creates many Express instances has every router in the process wrapped, including routers unrelated to docs. Without an opt-out, an APM or instrumentation library that also wraps `use` (for example OpenTelemetry express instrumentation) runs in an ordering the plan never tested. | architecture.md:83 (ADR-18), ST-001-scaffold.md:78 ("sideEffects must allow ... recorder"), impact-report.md:13 (process-global) |
| PF-5 | MEDIUM | Constitution vs ADR-11 | The constitution's canonical build is `npm run build` (tsc). The plan changes it to tsup. The plan also adds commands that the constitution does not list (`check:pack`, `mutation`), and it does not state that the constitution must be amended. | The Master or QA agents run the constitution's `tsc` build expecting `dist/`, but the plan's layout (`.cjs` and `.d.cts`) only comes from tsup. | PF-6 | LOW | ST-001 package.json shape | The top-level `"types": "./dist/index.d.ts"` sits alongside `"main": "./dist/index.cjs"` under `"type":"module"`. Legacy `node10` resolution then pairs CJS JS with ESM-flavoured types, which attw reports as "Masquerading as ESM" / "CJS resolves to ESM types". The `"module"` field is non-standard and redundant when `exports` is present. | `attw --pack` (ADR-11 gate) fails the `node10` profile in S-01 CI. The builder either loosens attw with `--profile node16` or reworks the fields late. Fix: point top-level `types` at `./dist/index.d.cts` and drop `module`. | ST-001-scaffold.md:78, architecture.md:76 |
