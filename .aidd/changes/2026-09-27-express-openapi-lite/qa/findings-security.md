| 1 | MEDIUM | `src/config/merge.ts:27-43` (`mergeTwo`) | `mergeTwo` iterates `Object.keys(override)` and assigns `result[key] = overrideValue` with no denylist for `__proto__`, so a plain-object config value carrying an own-enumerable `__proto__` key (as produced by `JSON.parse`, not an object literal) silently reassigns the merged object's `[[Prototype]]` instead of being copied as data. | Verified live (see Evidence): `mergeTwo({a:1}, JSON.parse('{"__proto__":{"polluted":"yes"}}'))` yields `out.polluted === 'yes'` and `Object.getPrototypeOf(out) === maliciousProto`. `validateOptions` (`src/config/validate.ts:34-49`) only rejects unknown keys one level deep for the `docs`/`openapi` groups (`checkRow` validates the whole sub-object shape via `row.check`, never recursing into that sub-object's own keys). `buildSpec` (`src/spec/build.ts:245`, `mergeOptions(DEFAULT_OPTIONS, config, {})`) and `route()` (`src/route/typed.ts:58`) both call `mergeOptions` → `mergeTwo` on `config.openapi.info`/`openapi.tags`/`securitySchemes` — two levels below what `validateOptions` inspects. If an application composes any part of `ApiDocsOptions` (e.g. `openapi.info`) from `JSON.parse` of external/tenant-supplied data — a pattern the PRD's config model (`createApiDocs(options)`, code-only config, no stated construction restriction) does not forbid — a value like `{"openapi":{"info":{"__proto__":{"title":"pwned"}}}}` swaps the prototype of the merged `info` object, letting attacker-chosen keys appear as inherited properties on config objects the rest of the spec builder treats as trusted merge output. This is object-prototype substitution reachable past the declared "unknown key" defense (AC-045), not merely a theoretical gadget. Blast radius is the specific merged object, not global `Object.prototype` — scored MEDIUM, not CRITICAL. |
| 2 | MEDIUM | `src/index.ts:4`, `src/introspect/auto-record.ts:34` | Importing the package's default entry point executes `autoRecord()` as a module-load side effect, unconditionally monkey-patching the process-wide `express` module's `Router` prototype and `application` object the moment the module is imported — before `createApiDocs()` is ever called. | A process that imports `express-api-docs` anywhere (even a test file referencing its types) causes every `Router`/`app.use()` call in that process — including calls from unrelated code sharing the same `express` module instance (hoisted `node_modules`, monorepo) — to run through the wrapped `use` (`src/introspect/recorder.ts:106-112`). Because the guard uses `Symbol.for('express-api-docs.v1.recorder')` (`src/core/types.ts:46`, a well-known cross-realm/cross-copy symbol), two independently loaded copies of this package at different versions in the same process will race on `installGuarded` (`recorder.ts:96-115`): whichever version's `autoRecord()` runs first wins the guard (`existing.protocol === PROTOCOL` short-circuits at `recorder.ts:98-102`), so the second copy's annotation logic silently never installs, with no warning beyond a `log.debug` on protocol mismatch (none at all on same-protocol silent reuse). | 3 | LOW | `src/docs/render.ts:36` (`renderdocs UIHtml`) | `data-url=${encodedUrl}` is emitted as an **unquoted** HTML attribute; `encodeSpecUrl` (render.ts:24-26) HTML-escapes quote characters but never escapes or rejects the space character, so a `specUrl`/`cdnUrl` containing a literal space terminates the unquoted attribute early and the remainder is parsed as additional attributes on the `<script>` tag. | `docs.specUrl` is developer/config-supplied per AC-043, so the direct path is narrow, but it is the exact value the file's own header comment (render.ts:1-3) claims is defended against injection ("carrying `</script>\"'&<`" — space is absent from that list and from `escapeHtml`). Given `docs.specUrl = 'https://example.com/openapi.json onerror=alert(document.domain)//'`, the output becomes `<script id="api-reference" data-url=&quot;https://example.com/openapi.json&quot; onerror=alert(document.domain)//&quot;...&quot;></script>` — the browser parses `onerror` as a real second attribute on the `<script>` element, which does fire on load failure. Quoting the attribute (`data-url="${encodedUrl}"`) closes this; the unquoted form is the root cause regardless of exact trigger conditions. |
| 4 | LOW | `src/docs/cdn.ts:8-10`, `src/docs/render.ts:37,53` | The `<script src>`/`<link href>` tags loading the docs UI from `cdn.jsdelivr.net` carry no `integrity=` (SRI) attribute, despite the URLs already being version-pinned (exactly what's needed to compute a static SRI hash). | If `cdn.jsdelivr.net` is compromised, DNS-hijacked, or intercepted by an on-path/TLS-trusted proxy, an attacker can serve modified JS for the pinned the docs UI version to every consumer's `/docs` endpoint; that script runs in the docs page's origin with no browser-side integrity check, enabling cookie/token theft or DOM-based follow-on attacks. Adding `integrity` hashes for the already-pinned versions is mechanically straightforward; the absence is an avoidable gap, not an inherent CDN limitation. |

## Evidence

Prototype-substitution repro (finding #1), run against the exact `isPlainDataObject`/`mergeTwo` logic from `src/config/merge.ts`:
```
$ node -e "<mergeTwo/isPlainDataObject copied verbatim from src/config/merge.ts>
const malicious = JSON.parse('{\"__proto__\":{\"polluted\":\"yes\"}}');
const out = mergeTwo({a:1}, malicious);
console.log('out.polluted:', out.polluted);
console.log('proto swapped:', Object.getPrototypeOf(out) === malicious.__proto__);
"
out.polluted: yes
proto swapped: true
```
Global `Object.prototype` was confirmed NOT polluted by this path in the same run (`({}).polluted === undefined` afterward) — blast radius is the specific merged object only.

`src/config/validate.ts:34-49` confirms `checkRow` never recurses past `docs.*`/`openapi.*` one level. `src/index.ts:4` / `src/introspect/auto-record.ts:34` confirmed by direct read: `autoRecord()` is a top-level call executed on import. `src/core/types.ts:46` confirms `RECORDER` uses `Symbol.for(...)` (global symbol registry). `src/docs/render.ts:36` and `src/docs/cdn.ts:8-10` confirmed by direct read.
