| 1 | CRITICAL | `src/spec/build.ts:107-131` (`pathParameters`, `queryParameters`) | When a Zod schema property resolves to a `$ref` (e.g. any schema tagged with `.meta({ id })` — Zod's documented, normal pattern for naming/reusing a schema, exactly what a consumer would do to get a reusable named definition), the builder extracts only `schema.properties[name]` and drops the schema's own `$defs` bag, emitting a dangling, unresolvable `$ref` that exists neither in the parameter's own schema nor in `components.schemas`. | Reproduced live against the actual built package (`npx vitest run` against a scratch test file using `createApiDocs({ schemaAdapter: zodAdapter })`, route `GET /things/:id` with `query: z.object({ a: Id, b: Id })` where `const Id = z.string().uuid().meta({ id: 'Id' })`, deleted after verification). `GET /openapi.json` on the real Express app returned `parameters: [{ in: 'query', name: 'a', schema: { $ref: '#/$defs/Id' } }, { in: 'query', name: 'b', schema: { $ref: '#/$defs/Id' } }]` with no `$defs` object anywhere in the document (`components` only ever holds `ProblemDetails`, per `src/spec/build.ts:266-269`). Feeding that exact response body to `@apidevtools/swagger-parser` — the validator AC-015 itself names as the acceptance check — via `SwaggerParser.validate()` **throws** (confirmed with a second probe test asserting `.rejects.toThrow()`, which passed). So for this ordinary, spec-sanctioned Zod usage, the shipped `/openapi.json` output is not a valid OpenAPI 3.1 document, directly falsifying AC-015 and AC-016. `requestBody`/`response` schemas (`requestBodyOf`/`responsesOf`, lines 133-171) are NOT affected, because they pass the *whole* adapter output (including its `$defs`) through untouched — only the per-property extraction used for path/query parameters truncates it, so the bug is scoped to `params`/`query` schemas specifically. None of the shipped tests (`test/spec/build.test.ts`, `test/serve/zero-config.test.ts`, `test/spec/ac023.test.ts`) exercise a `.meta({id})`/reused-schema case, so AC-015's swagger-parser check never observes this code path and the defect ships green. |
